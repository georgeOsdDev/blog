# はじめに
Container Apps サポート担当の谷津です。Azure Container Apps は、コンテナー化されたアプリケーションを効率的にデプロイできる便利なプラットフォームです。この投稿では、Azure Container Apps の Consumption プラン専用環境における構成要件について説明します。

Azure Container Apps では、様々な料金プランが用意されており、その中でも Consumption プランは使用量に応じた課金体系を採用しているため、小規模なワークロードや開発環境に適しています。

# Consumption 専用環境とは
Azure Container Apps の Consumption 専用環境は、完全にサーバーレスな実行環境で、使用したリソース分のみ課金されるコスト効率的なオプションです。この環境では、アプリケーションのトラフィックに応じて自動的にスケールアップ・ダウンが行われ、トラフィックがない場合はゼロまでスケールダウンされます。

## 主な特徴
- **コスト効率**: 使用したリソース分のみの課金
- **自動スケーリング**: トラフィックに応じた自動的なスケール調整
- **ゼロスケール**: アイドル時のコストゼロ
- **管理の簡略化**: インフラストラクチャ管理が不要

# 構成要件

## ネットワーク要件
### 仮想ネットワーク (VNet) の制限
Consumption 専用環境では、以下のネットワーク制限があります：

- **カスタム VNet の使用不可**: Consumption 専用環境では、カスタムの仮想ネットワークを使用することはできません
- **既定のネットワーク設定**: Microsoft が管理するネットワーク環境を使用します
- **プライベート エンドポイント**: サポートされていません

### 送信接続
- **インターネット接続**: 既定でインターネットへの送信接続が可能です
- **IP アドレス**: 固定の送信 IP アドレスは提供されません
- **ファイアウォール ルール**: 送信接続の制御には制限があります

## リソース制限
### CPU とメモリ
- **CPU**: 最大 2 vCPU まで
- **メモリ**: 最大 4 GB まで
- **一時ストレージ**: 限定された容量

### スケーリング制限
- **最大レプリカ数**: 環境によって制限されます
- **同時実行リクエスト**: レプリカあたりの同時実行数に制限があります

## ストレージ要件
### 永続ストレージ
- **Azure Files**: 制限付きサポート
- **ボリューム マウント**: 一部制限があります
- **一時ストレージ**: 利用可能ですが、レプリカの再起動時に失われます

### データ永続化
永続的なデータ保存が必要な場合は、外部のストレージサービス（Azure Storage、Azure Database など）を使用することを推奨します。

# セキュリティ要件

## 認証と承認
- **マネージド ID**: サポートされています
- **Azure Active Directory**: 統合可能です
- **カスタム認証**: アプリケーション レベルでの実装が必要です

## ネットワーク セキュリティ
- **HTTPS**: 既定で有効です
- **TLS 終端**: プラットフォーム レベルで処理されます
- **カスタム ドメイン**: サポートされていますが、証明書管理に制限があります

# 監視と診断

## ログとメトリクス
- **Azure Monitor**: 統合されています
- **Application Insights**: サポートされています
- **カスタム メトリクス**: 制限があります

## トラブルシューティング
- **コンソール アクセス**: 利用可能です
- **ログ ストリーミング**: リアルタイムでのログ確認が可能です

# 制限事項

## サポートされない機能
以下の機能は Consumption 専用環境ではサポートされていません：

1. **カスタム VNet 統合**
2. **専用ホスティング プラン**
3. **高度なネットワーク制御**
4. **大容量のストレージ要件**
5. **高いパフォーマンス要件のワークロード**

## 代替案
これらの機能が必要な場合は、Azure Container Apps の Dedicated プランまたは他の Azure サービスの使用を検討してください。

# 最適化のベスト プラクティス

## アプリケーション設計
1. **ステートレス設計**: アプリケーションはステートレスに設計することを推奨
2. **外部依存関係の最小化**: 起動時間を短縮するために依存関係を最小限に抑制
3. **効率的なコンテナー イメージ**: 軽量なベースイメージを使用

## パフォーマンス調整
1. **適切なリソース設定**: CPU とメモリの設定を最適化
2. **スケーリング設定**: 適切な最小・最大レプリカ数の設定
3. **ヘルス チェック**: 適切なヘルスチェックの実装

# まとめ
Azure Container Apps の Consumption 専用環境は、コスト効率的なコンテナー実行環境を提供しますが、いくつかの制限があります。これらの制限を理解し、適切に設計されたアプリケーションであれば、優れたパフォーマンスとコスト効率を実現できます。

より高度な機能やパフォーマンスが必要な場合は、Dedicated プランや他の Azure サービスの使用を検討することをお勧めします。
